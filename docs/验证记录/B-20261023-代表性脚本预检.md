## 2. 固定材料与边界

材料在 [`eval/cases/gap-threshold-v1`](../../eval/cases/gap-threshold-v1/)：一张程序绘制的确定性流程图、需求、精简模拟目录／SDK 约定和独立 `case.json`。它不是用户工程截图或真实 SDK；构造与读写调用形状引用根目录脚本示例，真实命名空间／程序集仍待取得 SDK 核对。目录按 ID 排列，不在目录中直接提供正确执行顺序。预期答案和模拟用例没有送给模型。

任务要求：读取工具 67 的 Distance，先舍入三位，按全局上下限的闭区间判定，向工具 2 写 gap／status／message。NaN、Infinity、倒置阈值及读取异常写 INVALID；必须给出完整脚本和图中执行顺序，不执行设备。

SDK shim 将 `GetValue`／全局读取和三个允许的写入映射为内存值。编译器为本机 .NET Framework 目录中的 C# 5 编译器 4.8.9232.0；**这不证明真实 .NET Framework 4.7.2 宿主、IMV 程序集或设备业务通过**。

## 4. 容量、资源与预算结论

- 原请求文本（含 system 和序列化材料）3239 UTF-8 字节；第一次反馈 5356 字节；第二次反馈 5969 字节。字节不冒充 token。
- 引擎日志的文字／联合 token 分别为 `823/1887`、`1342/2406`、`1552/2616`。本图的额外视觉部分为 1064 tokens，原字节透传且有实际图像编码日志。没有采用旧文本字节预算，也未将视觉计为零。
- 初次及第一次修复的观测输入分别小于 2560；第二次修复 **2616 超出 2560 共 56 tokens**。本次显式允许受控实验绕过未验证的发送前预算，因此请求实际发出；正式业务不能沿用这种放行方式。第二次修复也不满足“输入＋完整输出预留＋512”工程分配，不能以实际输出较短掩盖。
- 393 tokens 足够交付本个案最终短脚本，但没有测试原始两份完整示例、完整真实目录或真实 SDK 的容量。不能据此宣布 1024 输出上限满足工业脚本。
- 实际上下文 4096；日志显示 GPU offload 14/37 层，存在 CPU 分担。四次生成速度约 6.96～7.67 tokens/s；整卡采样峰值分别 3765、3651、3778、3743 MiB。采样命令结束后等待 1 秒，约 1.2 秒间隔；包含桌面及其他进程显存，不能视为进程精确峰值。
- `check_budget` 始终返回 `INPUT_BUDGET_UNVERIFIED`，配置 `Verified=true` 也不会凭标志启用。尚无已校准的 Ollama renderer／视觉计数器；事后计数仅供上述受控观察。普通文字／图片业务均不能凭此次实验声明预算已验证。
- 完成后正常卸载模型，`/api/ps` 返回空；引擎保留运行。未测真实推理取消、执行超时、下一任务收尾、断网复用、箭头对照图、业务 API 或公网。
