主会话对齐说明：分工和目录按 [实施规划](../实施规划.md)。S04 v0.4 已有可选图片契约草案，P0 落实 schema／样例后，本专项先与 S04 做 Fake 闭环，再接真实 VL；正式宿主适配后置。

## 1. 目标与边界

先用简易 C# 脚本 Demo，根据后续准备好的接口说明和示例，验证与服务端的连接及模型基础能力；后续再接入现有视觉软件的完整 C# 工具与 AI 面板。

目标用户、现有框架和元数据接口能力见 [主方案 R02、R04、R06](../主方案.md)。不能从示例同时引用 WinForms／WPF 的命名空间推断现有编辑器的真实 UI 技术。

服务协议由 [S04](04-服务端API与任务调度.md) 维护；模型生成规则由 [S01](01-模型能力与上下文.md) 维护；本专项负责 Demo 调用、后续用户交互、元数据接入与宿主编译反馈。当前只确认方案并维护本专项文档，尚未开始客户端开发或测试。

## 3. Demo 最小验证范围建议

下列为落实已确认路线的建议清单，均未执行；具体字段和调用顺序以届时交付的 S04 接口为准。

| 验证项 | Demo 行为与可确认的结果 |
| --- | --- |
| 服务连接 | 使用配置的业务 API 地址，分别查看服务可达、认证和就绪结果，避免把健康接口成功视为模型已可用 |
| 一次完整请求 | 加载一个短需求及固定上下文，提交后输出任务编号、排队／执行状态，终态后读取结果 |
| 基础模型能力 | 用少量固定示例观察代码生成、解释或修改效果；记录实际输入和返回，先人工判断是否符合要求 |
| 问题定位 | 输出错误码、任务／追踪编号和耗时；区分传输失败、任务失败和生成内容不符合要求 |
| 结果留存 | 保留本地输入样例和返回文本，供复测与 S06 报告引用；凭据不写入样例、结果或日志 |

异步任务采用文字状态即可，无需先做完整界面。按 S04 的任务／结果分离方式查询；提交前保留请求编号，响应丢失时先查回原任务，避免直接用新编号重复提交。取消、断线恢复等完整可靠性用例随后随 S04／S06 联调补齐，不把完整任务管理界面作为第一次连接测试的前提。若加入停止操作，其完成／停止／超时语义沿用 S04 第 7.4 节。

先显示状态和最终文本，不把逐字输出列为 Demo 必需项。Demo 不自动执行模型返回的代码；“请求成功”“模型完整返回”“宿主编译通过”“业务结果正确”分别记录。少量样例仅用于基础观察，不代表已经完成模型质量验收。

### 图文输入依赖

[S02 当前基线及第 6.6 节](02-模型与推理部署.md) 确定图文路线；S04 v0.4 已修订图片草案，但 schema／实际预算器尚未就绪。Demo 先短文本验证连接，再用固定 PNG 文件按 images 字段提交；图片选择／预览界面留给后续正式面板。图片任务不能因预算未验证而回退成普通文本 Base64。

提交默认超时建议 120 秒，查询／健康等 15 秒，活动任务约 3 秒轮询，具体以 S04 为准。保留 clientRequestId 跨超时查回；图片字节改变使用新请求编号。长上传、模型执行和排队分别计时，不只把 HttpClient 的一个超时同时套给全部操作。

这只是测试顺序建议，不撤回 S02 的图文需求，也不将纯文本测试记为看图能力通过。图片字段、限额和传输方式由 S04 明确，不能把图片 Base64 拼入普通文本字段代替视觉输入。

## 4. 正式 AI 面板草案

1. 选择新建或修改当前脚本，输入业务描述。
2. 自动读取当前流程元数据，用工具名称／变量名称显示可选来源。
3. 多来源时按 S01 询问或暂选并说明；关键业务语义缺失时澄清，不静默猜测。
4. 返回代码、业务说明与必要的流程配套调整。
5. 调用实际宿主编译检查并反馈错误；自动修复策略由 S01 定义。
6. 使用适当数据验证后确认应用，保留旧版本和恢复入口。

以上流程为后续集成建议，不属于当前 Demo 的交付要求。应用排队任务的结果前，按 S04 核对来源修订和当前脚本，避免覆盖期间已修改的代码。涉及相邻流程节点的自动修改、生产设备联调和运行中 AI 调用，尚未定义执行范围。

## 6. 接口就绪条件与后续交付

开始编写可调用真实服务的 Demo 前，需要后续实施提供：

- 可访问的业务服务地址、测试凭据及认证说明。
