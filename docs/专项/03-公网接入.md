仅服务器安装连接器；测试用户通过 HTTPS 地址调用。普通宽带主机主动建立出站连接，首轮无需购买云服务器、申请家庭宽带公网地址或配置入站端口映射。

在本机业务 API 已可用、且 `cloudflared` 已安装后，官方示例命令可以改为指向该 API。以下端口仅为示例，不代表本项目已定端口或已运行：

```powershell
cloudflared tunnel --url http://127.0.0.1:8080
```

适配约束：[Q]

- 新建隧道会得到新的临时域名；停止连接器后入口失效。客户端必须允许修改服务地址。
- 无在线保证；最多 200 个同时在途请求，超出返回 `429`。这是请求并发上限，不是用户数。
- 不支持 SSE。当前 S04 的短请求、提交任务后轮询结果草案与其相容；若以后采用 SSE，需要改选入口。
- 可选的 `--allowed-mail` 要求浏览器交互，不适合直接用于本项目 C# API 调用；此处使用 S04 的业务令牌认证。

5 位用户使用短请求，从协议形态看适合先试；这只是设计判断，不是实测容量或国内可用性承诺。实际用户网络表现不佳时直接试低成本备选，避免将排查临时入口变成模型评估的前置长期工作。

### 5.2 NATAPP 的预期操作量

官方支持 Windows 下载、`config.ini` 配置和 Windows 系统服务。[N4][N5][N6] 对本项目建议采用下列顺序：

1. 在目标主机确认业务 API 可通过本机回环地址访问，记录真实端口；模型是否就绪另验。
2. 账号按平台要求完成注册／认证，选择一个月 Web 隧道和平台二级域名，开启域名 HTTPS。使用平台二级域名可省去自备域名的 DNS 操作和自行申请入口证书；具体订单和可选后缀须登录核实。
3. 下载 Windows 客户端，在专用目录保存 `natapp.exe` 和本地 `config.ini`，用本地文件保存隧道令牌，不写入项目文档或源码。
4. 先前台运行，确认 `Tunnel Status Online` 和 `Forwarding` 地址，再从另一个实际外网测试 HTTPS 与业务认证；不能只凭连接器显示在线宣布整条链路通过。[N4]
5. 验证通过后安装为 Windows 服务，配置并检查开机启动／故障恢复；重启机器再次验收。官方服务安装需要 Windows 管理员权限，具体命令和恢复配置在选型后冻结。[N6]

公网层无需搭建 Linux 云主机、Docker、Nginx 或 Caddy，也不要求五位测试用户安装组网客户端。以上是方案依据和操作概览，不是已在目标机器测试通过的安装手册；不承诺固定分钟数完成。

## 6. 长期路线：固定托管入口或自建云入口

模型和实际使用价值达到要求后，再比较：

1. **继续使用付费托管隧道**：若线路、额度、故障处理和服务条件满足要求，可继续使用；没有必须迁移的时间点。
2. **Cloudflare 账号隧道＋自有域名**：可保留较少自建组件，获得固定入口；正式发布需要账号及接入 Cloudflare 的域名。[B] 官方包含免费隧道配额，[P] 但域名、附加产品和实际网络表现仍需分别评估。
3. **轻量云服务器＋frp＋Caddy**：需要掌握入口配置、日志和迁移能力，且有人承担维护时再选择。

```mermaid
    B --> C["云端 frps 的内部转发端口"]
    C <-->|"认证与 TLS 隧道"| D["Windows 主机 frpc"]
    D --> E["本机业务 API"]
    E --> F["本机推理引擎"]
```

- 云服务器提供稳定入口，无需 GPU；实际模型留在 Windows 主机。
- `frpc` 从普通宽带主动向云端 `frps` 建立连接。
- Caddy 管理域名 HTTPS 入口；内部转发端口限制在本机或受控网络。
- 隧道启用认证、TLS 和对端证书校验；不能把“默认加密”当成“已校验对端身份”。
- 用户访问业务 API，Ollama 推理端口不发布到公网。
- 云服务器使用 Linux 与目标 GPU 主机是否使用 WSL 是两个独立选择。

自建方案尚待选择云服务商、地域、域名、带宽／流量、TLS 方案和维护方式。正式报价应同时核对首购、续费和额外费用，不用促销首年价格代表长期成本；本轮不冻结云主机预算。

固定域名只减少地址变化，不代表链路获得高可用。无论入口如何选择，Windows 模型主机的电源、宽带、上行、进程和模型就绪状态仍会影响服务；云端只承担入口时，也不会提高本机模型的生成速度。

## 7. 保持后续切换成本可控

以下为与其他专项协调的建议，尚未修改或冻结其接口：

- **S04**：维持独立业务 API，任务提交后尽快返回任务 ID，生成在后台运行；避免将长时间模型生成绑定在一个公网 HTTP 响应上。短请求轮询本身不能证明模型具备合格体验，仍要独立记录生成耗时。
- **S05**：统一可配置的 `BaseUrl`、可单独撤销的用户令牌、可复用的调用层；更换入口主要调整地址／入口配置，任务字段与生成逻辑不随隧道服务改变。
- **监听边界**：Cloudflare／NATAPP 连接器和业务 API 同机时，可将 API 绑定本机回环地址；模型端口只供内部使用。Tailscale 方案需另配组网地址监听和访问规则，不能照搬回环绑定。
- **认证与数据路径**：免费入口同样需要业务认证与任务归属校验。初期使用脱敏样例；采用托管 HTTPS 入口前明确第三方中转和 TLS 终止位置，不能把 HTTPS 自动解释为中转服务无法接触明文。
- **S06**：分别记录入口连通耗时、HTTP 请求耗时、排队等待、模型推理耗时，防止因免费线路不稳而误判模型，也防止网络通畅掩盖模型质量问题。

## 8. 分阶段执行草案与切换条件

没有安装、账号注册、付费、隧道创建或外网测试；下表为建议步骤。

| 阶段 | 建议动作 | 完成依据／切换条件 |
| --- | --- | --- |
| 0：本机预检 | 用模拟结果 API 验证提交、查询、认证；再做少量本机模型预检 | 业务服务能独立运行，网络故障不会与模型故障混淆 |
| 1：选型与手册 | D 路线与 Windows 11 x64 已获确认；手册草案已建立，接着对齐 S04／S05 参数 | 入口无需再次确认；跨专项参数、账号实际字段和未验证步骤均有明确状态 |
| 2：外网与持续内测 | 根据选定路线从外网验证 API；B1 仅为可选补充测试 | 多用户能完成测试；确认连接／流量额度和重连行为；独立进行模型质量评估 |
| 3：正式方案评估 | 模型能力满足需求且确定持续使用后，比较长期托管与自建 | 实际网络报告、持续费用、维护负责人、域名和恢复方式均有依据 |

首轮网络检查清单：

1. 从不同外网测试健康检查、合法／非法令牌和提交／查询／取消，测试范围与 S04 定案接口一致。
2. 模拟长任务，确认提交迅速返回、后台任务继续运行、查询不依赖长连接；再接真实模型。
3. 约 5 位测试用户同时提交，核对排队、轮询、错误和实际流量；耗时与质量分开记录。
4. 重启连接器和临时中断网络，检查重连、原任务查询、幂等重试及临时地址变化后的恢复。
5. 对比本机与外网的同一测试任务；模型不可用、API 不可用、隧道不可用分别标记。
